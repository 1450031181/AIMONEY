## 1. 项目背景与目标

### 1.1 背景

幻方量化的核心能力可拆解为一条完整流水线：**海量数据 → 因子工厂 → 模型/策略组合 → 严格回测验证 → 组合优化与风控 → 全自动低延迟交易执行 → 实时监控与归因**。其本质不是「猜涨跌」，而是把研究流程工程化、把交易流程自动化，用系统纪律替代人工情绪。

本项目的目标是：把这条流水线**个人化、轻量化**，做成一套可在单机/单服务器上跑起来的全自动炒股工具——研究员只需写策略，系统负责取数、回测、风控、下单、盯盘、告警。

### 1.2 产品定位

> 一个「个人版量化研究 + 自动交易」一体化平台：白天自动跑策略、管仓位、控风险；夜间自动跑数据更新、因子计算、参数寻优、回测报告。

### 1.3 目标（一期验收后应达到）

| 编号 | 目标 | 衡量标准 |
| --- | --- | --- |
| G1 | 研究闭环 | 从写策略到看到完整回测报告，全流程 ≤ 30 分钟（含数据已就绪） |
| G2 | 回测可信 | 回测严格模拟 A 股 T+1、涨跌停、停牌、手续费、滑点，回测与模拟盘偏差 ≤ 15% |
| G3 | 全自动交易 | 盘前自动选股、盘中自动下单、盘后自动对账，人工只需处理告警 |
| G4 | 风险可控 | 支持的 6 类风控规则全部生效，最大回撤熔断可自动清仓 |
| G5 | 可观测 | 任意时刻可查持仓、浮盈、成交、信号来源、风控触发记录 |

### 1.4 非目标（本期明确不做）

- ❌ 高频交易（毫秒级/低延迟撮合），本项目定位中低频（日频～分钟频）
- ❌ 期货、期权、融资融券、场外衍生品
- ❌ 绕过券商官方接口的「打板外挂」「接口破解」类方案
- ❌ 承诺收益、代客理财、对外募集资金（合规红线）
- ❌ 分布式集群与自研撮合引擎（二期按需演进）

## 2. 名词解释

| 术语 | 说明 |
| --- | --- |
| 因子（Factor） | 对未来收益有预测能力的数值特征，如动量、估值、换手率 |
| IC / IR | 因子值与未来收益的相关系数 / 其均值比标准差，衡量因子有效性 |
| 事件驱动回测 | 按行情事件逐个推进、逐笔撮合的回测方式，贴近真实 |
| 向量化回测 | 用矩阵运算批量回测，快但细节模拟弱 |
| Walk-Forward | 滚动前进式样本外验证，防过拟合 |
| 风控前置（Pre-Trade） | 下单前校验，不通过则拒单 |
| 母子单 / 拆单 | 大单拆成小单分批成交，降低冲击成本 |
| T+1 | A 股当日买入不可当日卖出 |
| 程序化交易报备 | 依监管要求，程序化交易需通过券商向交易所报备 |

## 3. 用户角色

| 角色 | 关注点 | 主要操作 |
| --- | --- | --- |
| 策略研究员（主要用户） | 因子是否有效、策略是否赚钱 | 写策略、跑回测、看报告、调参 |
| 交易操作员（可同一人） | 今日该买什么、成交没有 | 看信号、审核/放行订单、盯盘 |
| 风控管理员（可同一人） | 有没有超限、要不要熔断 | 配置风控规则、处置告警 |
| 系统运维 | 任务有没有跑、数据全不全 | 看任务日志、数据质量报告、重启服务 |

## 4. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  控制台 Web（策略管理 / 回测报告 / 实时盯盘 / 风控 / 告警）      │
└──────────────────────────────────────────────────────────────┘
        │ REST + WebSocket（实时推送持仓、信号、日志）
┌──────────────────────────────────────────────────────────────┐
│  应用服务层（FastAPI）                                        │
│  ├ 数据服务   ├ 因子服务   ├ 回测服务   ├ 组合服务            │
│  ├ 风控服务   ├ 交易服务(OMS)  ├ 监控告警   ├ 任务调度         │
└──────────────────────────────────────────────────────────────┘
        │
┌───────────────┬───────────────┬───────────────┬──────────────┐
│ 策略引擎       │ 回测引擎       │ 执行引擎       │ 调度引擎      │
│ 信号生成       │ 事件驱动撮合    │ 拆单/下单/对账  │ 盘前盘中盘后   │
└───────────────┴───────────────┴───────────────┴──────────────┘
        │
┌──────────────────────────────────────────────────────────────┐
│ 数据层：行情(日/分钟) + 财务 + 指数成分 + 交易日历 + 另类数据    │
│ 存储：Parquet/DuckDB（列存）+ PostgreSQL（业务）+ Redis（缓存）  │
└──────────────────────────────────────────────────────────────┘
        │
┌──────────────────────────────────────────────────────────────┐
│ 外部接口：行情源（AkShare/Tushare/聚宽）+ 券商交易接口           │
│ （QMT/miniQMT、Ptrade、掘金，均需券商官方开通）                  │
└──────────────────────────────────────────────────────────────┘
```

**分层原则**：研究态（回测）与生产态（实盘）**共用同一份策略代码**，仅数据源与执行器不同。这是保证「回测→实盘」一致性的关键设计。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 单策略 5 年日频回测（全 A 股 5000 标的）≤ 3 分钟；分钟频 ≤ 15 分钟；支持并行加速 |
| 实时性 | 行情到信号 ≤ 2s；信号到下单 ≤ 1s（不含券商侧） |
| 可靠性 | 交易日关键任务可用性 ≥ 99%；服务异常不影响已下订单的跟踪与对账 |
| 数据安全 | 券商账号密钥加密存储（AES/国密），不明文落盘、不进日志、不进 Git |
| 幂等性 | 下单接口必须幂等，网络重试不产生重复委托 |
| 合规 | 遵守《证券市场程序化交易管理规定》相关要求，通过券商完成程序化交易报备 |
| 可扩展 | 新增数据源 / 券商接口 / 策略类型不改动核心引擎（插件化） |
| 可观测 | 结构化日志 + 关键指标（信号数、委托数、成交率、拒单率、任务耗时） |
| 环境 | 部署于个人电脑或云服务器（Linux 优先），单机可运行，无强依赖 K8s |
| 时区/日历 | 统一 Asia/Shanghai，所有时间按交易日历处理 |

## 9. 技术选型建议

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11（引擎/策略）+ TypeScript（前端） | 量化生态最全，策略开发成本低 |
| 计算 | Polars / NumPy / Pandas | Polars 列存计算快，适合全市场因子 |

| 回测 | **自研事件驱动引擎**（参考 backtrader/vnpy 思路，但内建 A 股规则） | 现成框架对 T+1、涨跌停、复权模拟不全 |
| 服务 | FastAPI + APScheduler（或 Celery/SQLModel） | 异步、自带 OpenAPI 文档 |
| 前端 | Vue 3 + Vite + TypeScript + ECharts | 图表丰富，开发快 |
| 交易 | QMT/miniQMT（个人可得性最好）、Ptrade、掘金 | 均需券商官方开通 |
| 部署 | Docker Compose | 一键起服务，单机可运维 |
| 行情源 | AkShare（免费兜底）+ Tushare Pro / 券商行情 | 成本可控，可插拔 |

## 11. 风险与合规

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 未来函数 / 数据泄漏 | 回测虚高，实盘必亏 | 财务数据按公告日对齐；因子计算禁止引用未来 bar；样本外验证强制 |
| 过拟合 | 样本内很好，实盘失效 | Walk-Forward、参数敏感性检验、限制参数数量 |
| 券商接口限制 | 无法自动下单 | 必须走券商官方接口并完成程序化交易报备；一期先模拟盘 |
| 涨跌停/停牌导致无法成交 | 信号失效 | 回测即模拟该约束，实盘未成交进入顺延队列 |
| 网络/服务中断 | 订单失控 | 本地订单状态落库 + 重启恢复 + 盘后对账 |
| 密钥泄露 | 资金风险 | 密钥加密存储、最小权限、不进日志、独立配置文件 |
| 合规风险 | 违规 | 不使用非官方接口；不代客理财；不承诺收益；保留全量交易审计 |
| 亏损风险 | 资金损失 | 强制风控熔断 + 单策略资金上限 + 小资金灰度上线 |

> **免责声明**：本系统为技术工具，不构成投资建议。任何策略的历史回测表现均不代表未来收益，实盘亏损风险由使用者自行承担。

## 附录 A：核心指标公式

- 年化收益：`(1 + 总收益)^(252 / 交易日数) - 1`
- 最大回撤：`max(1 - 当前净值 / 历史最高净值)`
- 夏普比率：`(年化收益 - 无风险利率) / 年化波动率`
- 卡玛比率：`年化收益 / 最大回撤`
- IC：`corr(因子值_t, 收益率_{t+1})`；ICIR：`mean(IC) / std(IC)`
- 换手率（双边）：`Σ|本期权重 - 上期权重| / 2 / 期间数 × 252`
