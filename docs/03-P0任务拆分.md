## 1. 拆分原则

1. **每个任务可独立验证**：有明确产出物 + 可执行验收命令，不做「写一半看不见」的任务；
2. **基础设施先行**：先有骨架、配置、日志、测试底座，再堆业务代码；
3. **数据正确性优先于功能数量**：宁可少接一个数据源，不可错一个复权因子——错误数据会污染后续所有策略结论；
4. **P0 不碰交易**：本阶段零下单逻辑，避免未验证就接触真实资金。

## 3. 任务详述

### T-01 仓库骨架与工程规范
- **内容**：按设计文档第 2 节创建目录；`pyproject.toml`（uv 或 poetry）锁定 Python 3.11、polars、pandas、duckdb、akshare、fastapi、pydantic-settings、structlog、pytest、ruff、mypy；`.gitignore` 排除 `data/`、`secrets.yaml`、`*.duckdb`。
- **验收**：`uv sync` 成功；`ruff check .` 与 `mypy engine` 无错误；`pytest` 可运行（0 用例也算通过）。

### T-02 配置与日志基础设施
- **内容**：`Settings`（pydantic-settings）分层加载 YAML + 环境变量；structlog JSON 日志，带 `trace_id`；`crypto.py` 用 AES-GCM 加解密 `secrets.yaml` 敏感字段。
- **验收**：配置非法（缺字段/类型错）启动即失败；日志中不出现明文 token/账号（用 grep 验证）。

### T-03 核心类型定义
- **内容**：实现设计文档第 3 节全部 dataclass 与 `Order` 状态机迁移校验（非法迁移抛异常）。
- **验收**：单测覆盖 `PENDING→SUBMITTED→PARTIAL→FILLED`、`PARTIAL→CANCELED`、`FILLED→CANCELED`（应失败）等分支。

### T-04 端口抽象层
- **内容**：`Protocol` 定义 + `Context` 对象（只读数据访问，无下单方法）。附 `InMemoryDataSource` 测试替身。
- **验收**：`Context` 无任何下单方法（代码审查）；测试替身可产出确定性假数据。

### T-05 交易日历与股票基础信息
- **内容**：同步交易日历（含 2005 年至今）、股票列表、上市/退市日、名称变更历史（用于识别 ST）。实现 `is_trade_day(d)`、`prev_trade_day(d)`、`next_trade_day(d)`。
- **验收**：抽查 2024—2026 年节假日与交易所公告一致；`prev/next` 在月初月末、长假边界正确。

### T-06 数据源适配器（AkShare）
- **内容**：实现 `daily()`（含 OHLCV、成交额、涨跌停价）、复权因子、停牌标记、指数成分；请求限速与失败重试；接口参数可配。
- **验收**：拉取 000001 近 1 年日线，与行情软件逐日比对（抽 10 日）误差为 0（价格）且成交量口径一致。

### T-07 Parquet 存储层
- **内容**：按 `year/month` 分区写入；同主键 upsert 覆盖；读取支持 `codes` + 日期区间 + 列裁剪；写入后统计行数并落 `data_version`。
- **验收**：重复同步同一区间两次，行数不变（幂等）；读取 1 年全 A 股日线 ≤ 2s。

### T-08 日线同步任务
- **内容**：增量同步（按本地最大日期续传）、并发拉取、失败标的记入补偿队列并在结束时重试、全程写 `task_log`（入参/耗时/成功失败数）。
- **验收**：断网中断后重跑可续传且无重复；人为让 3 只股票拉取失败，补偿任务能补齐。

### T-09 复权处理模块
- **内容**：前复权/后复权价格计算、`post → real` 价格还原（按最小变动价位取整）、除权日连续性校验。
- **验收**：选取 5 只有分红送转的股票，检查除权日总收益无跳变；还原价与当日真实盘口一致。

### T-10 指数成分与股票池
- **内容**：`dim_index_member`（含 `in_date/out_date`）+ `universe(as_of, index_code)`，支持 `exclude_st` / `min_list_days` / `exclude_new_days` / 停牌剔除。
- **验收**：2023-06-30 的沪深300 成分数 = 300（允许临时调整差异并说明）；ST 与次新过滤生效。

### T-11 数据质量校验与日报
- **内容**：6 类校验（缺失率、异常涨跌幅、价格 ≤ 0、重复主键、非停牌零成交、成交量突增 10 倍）；输出 `quality_report.json` + 控制台表格；FAIL 时写 Redis 门禁标志 `trade_gate=closed`。
- **验收**：人工注入 3 类脏数据，规则全部命中且报告定位到具体 `code+date`；门禁标志被正确写入。

### T-12 DuckDB 查询层与数据覆盖接口
- **内容**：DuckDB 建视图指向 parquet；实现 `datahub/reader.py` 统一查询 API；提供 `GET /api/v1/data/coverage` 返回各数据集起止日期、标的数、最新同步时间。
- **验收**：接口返回结果与实际数据一致；查询走分区裁剪（打印执行计划确认 scan 范围）。

### T-13 CLI 与数据读取骨架
- **内容**：`aimoney-data sync|list|check|coverage` 命令行；`--start/--end/--codes` 参数。
- **验收**：`aimoney-data check` 输出质量报告并返回非零退出码（当 FAIL 时）。

### T-14 分钟线同步（P1 加档）
- **内容**：1/5/15/30/60min 分钟线分区存储；数据量大，按需按标的拉取。
- **验收**：单只股票 1 年 5min 数据完整，时间戳与交易日历对齐。

### T-15 财务数据同步（P1 加档）
- **内容**：三大报表 + PE/PB/ROE 等指标，**以公告日 `ann_date` 为可见日**入库。
- **验收**：任取 1 只股票，用 `ann_date <= 2024-06-30` 查询不到 2024 年中报之后的财报（防未来函数）。

### T-16 端到端联调与 P0 验收
- **内容**：全新环境按 README 从零跑通「同步 → 校验 → 查询 → 覆盖报告」；产出 P0 验收报告（数据完整性、同步耗时、查询性能、质量结论、遗留问题）。
- **验收**：需求文档验收标准第 1 条通过——全 A 股 3 年以上日线 + 复权因子本地可用，质量报告无严重异常。

## 5. P0 阶段风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| AkShare 接口不稳定/字段变更 | 同步失败或数据错位 | 适配器隔离变更点 + 拉取后字段校验 + 双源可切换。**已实测发生**：`stock_zh_a_hist` 在短时间多次调用后返回 `RemoteDisconnected`，重试 4 次后抛出 `DataSourceError`（未产生脏数据）；联网用例已用 `network` 标记隔离，默认套件不受影响 |
| 历史复权因子不完整 | 回测收益失真 | T-09 专项验收；缺失时用「前复权收盘价反推」兜底并标记告警 |
| 涨跌停价字段缺失 | 后续回测撮合规则无法模拟 | 用 `前收盘价 × (1 ± 涨跌幅)` 计算，ST/科创/北交所分别设阈值并标记 `computed` |
| 停牌识别口径混乱 | 误判可交易 | 以「成交量 = 0 且无行情行」双条件判定，人工抽查确认 |
| 数据量增长导致查询变慢 | 后续回测性能不达标 | 分区 + DuckDB 列裁剪；预留 ClickHouse 演进路径 |
